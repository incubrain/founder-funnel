## Overview

The VRT module provides visual regression testing via Playwright screenshots and pixelmatch comparison.

::callout{icon="i-lucide-info" color="info"}
This module is dev-only. It registers a bare `/__vrt` route for screenshot capture but adds nothing to production builds.
::

## Configuration

```ts [nuxt.config.ts]
vrt: {
  enabled: true,    // default: true (dev-only regardless)
  route: '/__vrt',  // VRT route prefix
}
```

## How VRT Works

1. The VRT module registers a dev-only `/__vrt` route with a bare layout (no header, footer, or banner)
2. Tests open a Playwright browser, navigate to `/__vrt`, and screenshot elements by `data-testid`
3. Screenshots are compared against committed baselines using [pixelmatch](https://github.com/mapbox/pixelmatch){target="_blank"}
4. Differences produce diff images highlighting changed pixels in red

## Running VRT

```bash
# Compare against baselines
pnpm test:vrt

# Update baselines (accept intentional changes)
pnpm test:vrt:update
```

## File Locations

```
test/vrt/
├── __screenshots__/
│   ├── section-hero.png        ← Committed baselines
│   ├── section-benefits.png
│   ├── __current__/            ← Current captures (gitignored)
│   └── __diff__/               ← Diff images (gitignored)
└── sections.test.ts            ← Test file
```

## Writing VRT Tests

Import helpers from the layer:

```ts [test/vrt/sections.test.ts]
import { screenshotAllSections, screenshotByTestId } from '@incubrain/foundry/modules/vrt/shared/helpers'

describe('Landing Page Sections', () => {
  it('all sections match baselines', async () => {
    await screenshotAllSections()
  })
})

describe('Convert Components', () => {
  it('form matches baseline', async () => {
    await screenshotByTestId('convert-form')
  })
})
```

### screenshotAllSections()

Discovers all `section-*` data-testids on the page, screenshots each, and compares against baselines. Throws descriptive errors on failure with per-section diff percentages.

### screenshotByTestId(testId)

Screenshots a single element and compares against its baseline.

### VRT Options

Both helpers accept options:

| Option | Default | Description |
|---|---|---|
| `baseUrl` | `http://localhost:3000` | Dev server URL |
| `vrtPath` | `/__vrt` | VRT route prefix |
| `pagePath` | `/` | Page to screenshot |
| `threshold` | `0.1` | Pixel comparison threshold |
| `maxDiffRatio` | `0.05` | Maximum allowed diff percentage |
| `update` | `false` | Update mode (accept new baselines) |

## Vitest Configuration

VRT config is defined in `vitest.vrt.config.ts`:

```ts [vitest.vrt.config.ts]
import { createVrtConfig, createGlobalSetup } from '@incubrain/foundry/modules/vrt/shared'

export default createVrtConfig({
  screenshotDir: './test/vrt/__screenshots__',
  globalSetup: createGlobalSetup({ port: 3000 }),
})
```

`createGlobalSetup()` automatically starts a dev server before tests and kills it after.

## When to Run VRT

After modifying any of these:
- `*.vue` files in `components/`, `layouts/`, `pages/`
- `*.css` files in `assets/`
- Content config files that affect page structure
- The VRT module itself

## Interpreting Failures

- **Diff images** in `__diff__/` show changed pixels in red
- **Intentional changes:** Run `pnpm test:vrt:update` to accept new baselines, then commit the updated PNGs
- **Unintentional changes:** Fix the regression before committing

## CI Behavior

The VRT job in CI uses update mode to avoid false positives from cross-platform font rendering differences. It runs only on PRs that touch visual files.
