## Overview

The docs module provides the documentation layout, sidebar navigation, search, citations, glossary, and bibliography features. Each sub-feature can be individually disabled.

This module is what makes `appLayout: 'docs'` available. If you prefer a different docs solution (e.g., [Docus](https://docus.dev){target="_blank"}), disable this module entirely.

## Configuration

```ts [nuxt.config.ts]
docs: {
  enabled: true,      // default: true — the docs layout and core components
  search: true,       // default: true — useSearch composable + search button
  citations: true,    // default: true — useCitations, Bibliography, Cited, SourcesTable
  glossary: true,     // default: true — useGlossary, GlossaryTable, Defn
}
```

| Option | Default | What It Controls |
|---|---|---|
| `enabled` | `true` | Docs layout, sidebar components, page header links |
| `search` | `true` | `useSearch` composable, search button in sidebar |
| `citations` | `true` | `useCitations`, `useSourcesTable`, `Bibliography`, `Cited`, `SourcesTable` |
| `glossary` | `true` | `useGlossary`, `GlossaryTable`, `Defn` |

When `enabled` is `false`, the module provides a no-op `useSearch` stub so `app.vue` doesn't break.

## Layout

The `docs` layout provides:
- Left sidebar with navigation tree and search button
- Right sidebar with table of contents
- Bibliography section (when citations enabled)
- Page header with copy/edit actions

Assign it to routes in `nuxt.config.ts`:

```ts [nuxt.config.ts]
routeRules: {
  '/docs/**': { appLayout: 'docs' },
}
```

## Components Provided

### Core (always registered when enabled)

- `DocsAsideLeftBody` — Sidebar navigation tree
- `DocsAsideLeftTop` — Search button above sidebar
- `DocsAsideRightBottom` — Links below table of contents
- `DocsPageHeaderLinks` — Copy/edit actions in page header

### Citations (when `citations: true`)

- `Bibliography` — Renders all cited references at the bottom of the page
- `Cited` — Inline citation marker (used via `:cited` MDC syntax)
- `SourcesTable` — Grouped, searchable reference table

### Glossary (when `glossary: true`)

- `GlossaryTable` — Searchable table of all glossary terms
- `Defn` — Inline term marker with hover definition (used via `:defn` MDC syntax)

## Search

Control which collections appear in search results via `app.config.ts`:

```ts [app/app.config.ts]
content: {
  collections: {
    searchable: ['docs', 'pages', 'decisions'],
  },
}
```

::callout{icon="i-lucide-alert-triangle" color="warning"}
**Important:** Only collections listed in `searchable` are indexed. Data collections (FAQ, config, team) are NOT searchable by default.
::

### How It Works

1. `useSearch()` composable fetches search sections from all searchable collections
2. Data is loaded lazily on the client (`server: false`) to avoid blocking initial render
3. `app.vue` passes search data to `UContentSearch`

The search button appears in the header (when `showSearch: true` in navigation config) and in the docs sidebar via `DocsAsideLeftTop`.

## Citations

Inline citations reference academic or professional sources. Use the `:cited` MDC component:

```md
Light pollution affects 80% of the world's population :cited[according to a recent study]{#atlas-2016}.
```

This renders a superscript `[1]` link that:
- Shows the source domain in a tooltip on hover
- Links to the PDF or URL of the reference
- Adds the citation to the page's bibliography

### Multiple Citations

```md
This is well documented :cited[in the literature]{#smith-2020,jones-2021}.
```

Renders as `[1,2]` with both citations tracked.

### Invalid Citations

In development, invalid citation IDs show a red `[?id]` with fuzzy-match suggestions in the tooltip. This helps catch typos without breaking production.

### Bibliography

Add `<Bibliography />` to any page or layout to render all cited references at the bottom. The docs layout includes this automatically.

References are ordered by first citation appearance and show:
- Numbered index
- Credibility score badge (1–10)
- Date, author, title
- Description
- PDF/URL link

### References Collection

Citations reference sources defined in the `references` collection:

```yaml [content/references/ecology.yml]
category:
  id: ecology
  label: Ecology
sources:
  - id: atlas-2016
    title: World Atlas of Artificial Night Sky Brightness
    author: Falchi et al.
    date: "2016-06-10"
    description: Global light pollution mapping study.
    credibilityScore: 9
    affiliation: academic
    pdf: https://example.com/atlas-2016.pdf
    url: https://doi.org/10.1126/sciadv.1600377
```

### Sources Table

The `SourcesTable` component renders all references in a grouped, searchable table with expandable categories, affiliation badges, and PDF/URL action buttons.

## Glossary

Define terms that can be referenced inline with hover definitions:

```md
The :defn[DSI]{#org-dsi} has published guidelines on this topic.
```

This renders with a dotted underline. On hover, a popover shows the term definition, abbreviation, and category. Clicking navigates to the glossary page.

### Glossary Collection

```yaml [content/glossary/organizations.yml]
category:
  id: organizations
  label: Organizations
  color: primary
terms:
  - id: org-dsi
    term: DarkSky International
    abbreviation: DSI
    definition: A non-profit organization combating light pollution worldwide.
```

### Glossary Table

The `GlossaryTable` component renders a searchable table of all glossary terms. URL query sync lets you link directly to a search: `/resources/glossary?search=dsi`.

## Internal Links

Internal links (relative or absolute paths within your site) automatically get hover popovers with page metadata:

```md
See [our research](/docs/research/ecology) for details.
See [the overview](research/ecology) for more context.
```

Links that don't start with `http://`, `https://`, `mailto:`, or `tel:` are treated as internal and show a popover with the page's title and description on hover.

You can still use the explicit `internal:` prefix if needed:

```md
See [our research](internal:research/ecology) for details.
```

## Enabling Content Features

1. Enable the `docs` module with the sub-features you need in `nuxt.config.ts`
2. Add the relevant collections to `content.config.ts` (references, glossary)
3. Add collection mappings to `app.config.ts`
4. Create YAML content files in the appropriate directories
5. Use `:cited`, `:defn`, and `internal:` syntax in Markdown
