## Overview

The highlight-and-comment module is a **dev-only** documentation review tool. Select text on any docs page, leave a comment, and it gets logged to a local JSONL file. AI agents can read the log to fix issues, or you can review them manually.

::callout{icon="i-lucide-info" color="info"}
This feature only loads in development mode. It adds zero weight to production builds.
::

## How It Works

1. **Select text** on any docs page — a popover appears
2. **Write a comment** and your name — submit with the button or `Cmd+Enter`
3. The comment is saved to `.comments/review.jsonl` on disk
4. **Yellow highlights** appear on commented text
5. Click any highlight to open the **review panel**
6. **Resolve** comments when the issue is fixed

## Review Panel

A floating button in the bottom-right corner shows the open comment count. Click it to open a non-blocking slide-over panel listing all comments for the current page.

Comments are grouped by status:
- **Open** — active issues needing attention
- **Resolved** — completed reviews (collapsed by default)

## Log File Format

Comments are stored in `.comments/review.jsonl` — one JSON object per line:

```json
{
  "id": "c_8fd63e65",
  "page": "/docs/getting-started/introduction",
  "selectedText": "validation tool for technical founders",
  "anchor": {
    "headingId": "what-is-foundry",
    "blockIndex": 0,
    "textOffset": 5,
    "textLength": 40
  },
  "comment": "This phrasing could be clearer",
  "author": "drew",
  "status": "open",
  "createdAt": "2026-02-17T10:30:00.000Z"
}
```

The `selectedText` field is the key for AI agents — they can grep for it in the markdown source to find the exact location.

## API Endpoints

Both endpoints are dev-only and return 404 in production.

### GET /api/_comments

Returns comments, optionally filtered by page.

```bash
# All comments
curl http://localhost:3000/api/_comments

# Comments for a specific page
curl "http://localhost:3000/api/_comments?page=/docs/getting-started/introduction"
```

### POST /api/_comments

Creates a new comment or resolves an existing one.

```bash
# Create
curl -X POST http://localhost:3000/api/_comments \
  -H "Content-Type: application/json" \
  -d '{"page":"/docs/foo","selectedText":"some text","anchor":{"headingId":"overview","blockIndex":0,"textOffset":0,"textLength":9},"comment":"Fix this","author":"drew"}'

# Resolve
curl -X POST http://localhost:3000/api/_comments \
  -H "Content-Type: application/json" \
  -d '{"action":"resolve","id":"c_8fd63e65"}'
```

## Using with AI Agents

The JSONL format is designed for agent consumption. Point your agent at the log file:

> Read `.comments/review.jsonl` and fix all open comments. For each comment, find the `selectedText` in the markdown source file, apply the fix described in the `comment` field, and mark the comment as resolved via POST /api/_comments.

Future versions will include an MCP tool (`review-comments`) that exposes the log directly to agents via the Model Context Protocol.

## Configuration

The module is enabled by default in development. To disable it or change the log file path:

```ts [nuxt.config.ts]
comments: {
  enabled: false,           // disable the module
  logFile: '.review/log.jsonl', // custom log file path
}
```

The `.comments/` directory is gitignored by default. To share review comments with your team, remove it from `.gitignore`.
