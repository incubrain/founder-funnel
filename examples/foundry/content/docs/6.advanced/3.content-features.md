## Overview

These features are designed for **documentation-heavy sites** (like the AstronEra example). Most validation landing pages won't need them. They're opt-in — only activate when you add the relevant content collections.

## Citations

Inline citations reference academic or professional sources. Use the `:cited` MDC component:

```mdc
Light pollution affects 80% of the world's population :cited[according to a recent study]{#atlas-2016}.
```

This renders a superscript `[1]` link that:
- Shows the source domain in a tooltip on hover
- Links to the PDF or URL of the reference
- Adds the citation to the page's bibliography

### Multiple Citations

```mdc
This is well documented :cited[in the literature]{#smith-2020,jones-2021}.
```

Renders as `[1,2]` with both citations tracked.

### Invalid Citations

In development, invalid citation IDs show a red `[?id]` with fuzzy-match suggestions in the tooltip. This helps catch typos without breaking production.

## Bibliography

Add `<Bibliography />` to any page or layout to render all cited references at the bottom. The docs layout includes this automatically.

References are ordered by first citation appearance and show:
- Numbered index
- Credibility score badge (1–10)
- Date, author, title
- Description
- PDF/URL link

## References Collection

Citations reference sources defined in the `references` collection:

```yaml [content/references/ecology.yml]
category:
  id: ecology
  label: Ecology
sources:
  - id: atlas-2016
    title: World Atlas of Artificial Night Sky Brightness
    author: Falchi et al.
    date: "2016-06-10"
    description: Global light pollution mapping study.
    credibilityScore: 9
    affiliation: academic
    pdf: https://example.com/atlas-2016.pdf
    url: https://doi.org/10.1126/sciadv.1600377
```

## Glossary Terms

Define terms that can be referenced inline with hover definitions:

```mdc
The :defn[DSI]{#org-dsi} has published guidelines on this topic.
```

This renders with a dotted underline. On hover, a popover shows the term definition, abbreviation, and category. Clicking navigates to the glossary page.

### Glossary Collection

```yaml [content/glossary/organizations.yml]
category:
  id: organizations
  label: Organizations
  color: primary
terms:
  - id: org-dsi
    term: DarkSky International
    abbreviation: DSI
    definition: A non-profit organization combating light pollution worldwide.
```

## Glossary Table

The `GlossaryTable` component renders a searchable table of all glossary terms. URL query sync lets you link directly to a search: `/resources/glossary?search=dsi`.

## Sources Table

The `SourcesTable` component renders all references in a grouped, searchable table with expandable categories, affiliation badges, and PDF/URL action buttons.

## Internal Links

Use the `internal:` prefix in Markdown links to get hover popovers with page metadata:

```mdc
See [our research](internal:research/ecology) for details.
```

The link resolves to the full path (e.g., `/darksky/research/ecology`) and shows a popover with the page's title and description on hover.

## Docs Navigation Auto-Redirect

When using the docs layout, directory routes automatically redirect to the first child page. This prevents 404 errors when navigating to section paths.

### How It Works

The layer includes server middleware (`layer/server/middleware/docs-redirect.ts`) that:
- Intercepts requests to `/docs/*` directory paths
- Queries the docs navigation tree
- Redirects to the first child page if the directory has no `index.md`

**Example**: `/docs/getting-started` → `/docs/getting-started/introduction`

This matches the Nuxt.com docs behavior and works seamlessly with the `navigation.yml` pattern where directories have metadata files instead of index pages.

### Directory Structure

Each docs subdirectory should include:
- `navigation.yml` — Title and icon for sidebar display
- Numbered content files (1.intro.md, 2.setup.md, etc.)
- NO `index.md` file (conflicts with navigation.yml)

When a user navigates to the directory URL, they're automatically sent to the first numbered file.

## Enabling These Features

1. Add the relevant collections to `content.config.ts` (references, glossary)
2. Add collection mappings to `app.config.ts`
3. Create YAML content files in the appropriate directories
4. Use `:cited`, `:defn`, and `internal:` syntax in Markdown
5. For docs, add `navigation.yml` to each subdirectory
