## Overview

The multi-config system lets a single codebase serve multiple brands or configurations. Set `NUXT_PUBLIC_CONFIG_SOURCE` to switch which content directory is used.

## When You Need This

Most projects don't need multi-config. It's designed for:

- **Monorepos** where multiple brands share the same layer
- **Showcase vs starter** separation (the Foundry monorepo uses this)
- **White-label** products with brand-specific content

If you scaffolded with `create-foundry`, you're using a single-config setup and can skip this page.

## How It Works

The `config-resolver.ts` utility in `shared/` resolves directory paths based on the config source:

```ts
import { getActiveConfigSource } from '@incubrain/foundry/config-resolver'

const config = getActiveConfigSource(resolve)
// config.contentDir → resolved content directory
// config.publicDir  → resolved public directory
// config.envDir     → resolved .env directory
```

## Environment Variable

```env
NUXT_PUBLIC_CONFIG_SOURCE=root     # Use root-level config
NUXT_PUBLIC_CONFIG_SOURCE=foundry  # Use foundry-specific config
```

When not set, the app uses its own `content/` and `public/` directories as normal.

## Config Module

The layer's config module (`modules/config.ts`) runs at build time to auto-detect:

- **Site name** from `package.json`
- **Site URL** from environment variables (checks Vercel, Netlify, GitLab, Cloudflare)
- **Foundry version** from the layer's `package.json`

These are merged into `nuxt.options.site`, `appConfig.header`, `appConfig.seo`, and `appConfig.foundry` using `defu` — your explicit values always take priority.
