Foundry configuration lives in four places, each with a distinct purpose.

## Site Config

**File:** `content/config/site.yml`

Business identity and social links. Referenced by the footer, social components, and RSS feeds.

```yaml [content/config/site.yml]
business:
  name: "My Startup"
  legalName: "My Startup LLC"
  foundingYear: 2026
  logo: "/favicon-96x96.png"
  mission: "Helping founders validate faster."

socials:
  x: https://x.com/yourhandle
  github: https://github.com/yourrepo
  linkedin: https://linkedin.com/in/yourprofile
```

| Field | Required | Description |
|---|---|---|
| `business.name` | Yes | Display name used in footer copyright and metadata |
| `business.legalName` | Yes | Legal entity name for copyright |
| `business.foundingYear` | Yes | Year shown in copyright line |
| `business.logo` | Yes | Path to logo image (from `public/`) |
| `business.mission` | Yes | Mission statement, used in meta descriptions |
| `socials` | No | Key-value pairs of platform name to profile URL |

Social keys are matched to icons automatically — `x` gets the X/Twitter icon, `github` gets the GitHub icon, and so on. Any key maps to `i-simple-icons-{key}`.

## Navigation Config

**File:** `content/config/navigation.yml`

Controls the header, footer, and optional site banner. This is the single source of truth for all navigation links.

### Header

```yaml [content/config/navigation.yml]
header:
  title: My Startup
  socials:
    x: https://x.com/yourhandle
    github: https://github.com/yourrepo
  navigation:
    - label: About
      icon: i-lucide-info
      to: /about
    - label: Pricing
      icon: i-lucide-credit-card
      to: /offers/pricing
  showSearch: true
  showColorMode: true
```

| Field | Default | Description |
|---|---|---|
| `header.title` | Site name | Text next to logo |
| `header.socials` | — | Social links shown in header (icon buttons) |
| `header.navigation` | — | Main navigation links |
| `header.showSearch` | `true` | Show the search button |
| `header.showColorMode` | `true` | Show the light/dark mode toggle |

### Footer

```yaml [content/config/navigation.yml]
footer:
  columns:
    - label: Product
      children:
        - label: Features
          icon: i-lucide-star
          to: /features
        - label: Pricing
          icon: i-lucide-credit-card
          to: /offers/pricing
    - label: Company
      children:
        - label: About
          to: /about
        - label: Blog
          to: https://blog.example.com
          target: _blank
  bottom:
    - label: Privacy Policy
      to: /privacy
    - label: Terms of Service
      to: /terms
```

Footer columns support nested children. Bottom links appear below the columns on a single line.

### Banner

```yaml [content/config/navigation.yml]
banner:
  id: launch-2026
  icon: i-lucide-megaphone
  title: "We just launched! Check out our offer."
  to: /offers/launch
  color: primary
  close: true
  actions:
    - label: Learn More
      to: /offers/launch
      color: primary
      variant: solid
      size: xs
```

| Field | Default | Description |
|---|---|---|
| `banner.id` | — | Unique ID (used to remember dismissal in localStorage) |
| `banner.icon` | — | Leading icon |
| `banner.title` | — | Banner text |
| `banner.to` | — | Link when clicking the banner text |
| `banner.color` | `'primary'` | Color theme: `primary`, `neutral`, `success`, `warning`, `error` |
| `banner.close` | `false` | Show close button |
| `banner.actions` | — | Array of button actions (label, to, icon, color, variant, size) |

Set `banner` to `null` or omit it entirely to disable the banner.

## App Config

**File:** `app/app.config.ts`

Runtime configuration that controls how the Foundry layer behaves. This is where you map content collections to routes.

```ts [app/app.config.ts]
export default defineAppConfig({
  title: 'My Startup',
  description: 'Validating our next big thing',
  url: 'https://mystartup.com',

  logo: {
    light: '/logo-light.svg',
    dark: '/logo-dark.svg',
    alt: 'My Startup Logo',
  },

  content: {
    collections: {
      // Page collections (type: 'page' = routable)
      pages: { name: 'pages', type: 'page', prefix: '/', backLabel: 'Back' },
      docs: { name: 'docs', type: 'page', prefix: '/docs' },

      // Data collections (type: 'data' = queried, not routed)
      faq: { name: 'faq', type: 'data' },
      config: { name: 'config', type: 'data' },
      navigation: { name: 'navigation', type: 'data' },
      team: { name: 'team', type: 'data' },

      // Which collections are included in search
      searchable: ['pages', 'docs'],
    },
    defaultAuthor: 'founder',
    routing: {
      offers: '/offers',
      success: '/success',
    },
  },
})
```

### Collection Configuration

Each collection in `content.collections` can be a string shorthand (just the name) or an object:

| Field | Type | Description |
|---|---|---|
| `name` | `string` | Collection name as defined in `content.config.ts` |
| `type` | `'page' \| 'data'` | Whether the collection generates URL routes |
| `prefix` | `string` | URL prefix for page collections (e.g., `/docs`) |
| `backLabel` | `string` | Label for back navigation in article layouts |

The `searchable` array determines which collections appear in the content search modal.

### Routing

`content.routing` defines paths that aren't tied to a specific collection:

| Field | Default | Description |
|---|---|---|
| `offers` | `'/offers'` | Base path for offer detail pages |
| `success` | `'/success'` | Base path for post-conversion success pages |

### Logo

| Field | Description |
|---|---|
| `logo.light` | Logo image for light mode |
| `logo.dark` | Logo image for dark mode |
| `logo.alt` | Alt text for the logo |

### GitHub Integration (Optional)

```ts
github: {
  url: 'https://github.com/your-org/your-repo',
  branch: 'main',
  rootDir: '.',
}
```

Set `github: false` to disable "Edit on GitHub" links in the docs layout. When enabled, the docs layout shows edit and report links that point to the correct file in your repository.

### Table of Contents (Optional)

```ts
toc: {
  title: 'On This Page',
  bottom: {
    title: 'Community',
    links: [
      { icon: 'i-lucide-message-circle', label: 'Discord', to: 'https://discord.gg/yourserver', target: '_blank' },
    ],
  },
}
```

Shown in the right sidebar of the docs layout.

## Environment Variables

Environment variables configure integrations and runtime behavior. Create a `.env` file from `.env.example`:

### Site

| Variable | Description |
|---|---|
| `NUXT_PUBLIC_SITE_URL` | Your production URL (e.g., `https://mystartup.com`) |

### Analytics (Umami)

| Variable | Description |
|---|---|
| `NUXT_PUBLIC_SCRIPTS_UMAMI_ANALYTICS_WEBSITE_ID` | Umami website ID |
| `NUXT_PUBLIC_SCRIPTS_UMAMI_ANALYTICS_SCRIPT_INPUT_SRC` | Umami script URL |

Umami is mocked in development and active in production automatically. See [Umami docs](https://umami.is/docs){target="_blank"} for setup.

### Webhooks

| Variable | Description |
|---|---|
| `NUXT_WEBHOOK_URL` | Webhook destination URL(s), comma-separated for multiple |
| `NUXT_TELEGRAM_CHAT_ID` | Required if using Telegram webhooks |

Platform is auto-detected from the URL. See [Webhooks](/docs/events/webhooks) for details.

### Structured Logging (evlog)

| Variable | Description |
|---|---|
| `NUXT_SENTRY_DSN` | Sentry DSN for error tracking |
| `NUXT_AXIOM_TOKEN` | Axiom API token |
| `NUXT_AXIOM_DATASET` | Axiom dataset name |
| `NUXT_POSTHOG_API_KEY` | PostHog API key |

These are consumed by the drain plugin in `server/plugins/evlog-drain.ts`. Uncomment the relevant drain to enable it.

## Config Resolution Order

Foundry uses [`defu`](https://github.com/unjs/defu){target="_blank"} for deep merging. Your values always take priority:

1. **Your `nuxt.config.ts`** — highest priority
2. **Layer `nuxt.config.ts`** — defaults for everything
3. **Config module** — auto-detects site URL, name from `package.json`, foundry version

This means you only need to set what you want to change. Everything else falls back to sensible defaults.
