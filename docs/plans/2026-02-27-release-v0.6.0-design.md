```markdown
## [0.6.0] - 2026-02-27

### Added

- **SectionWrapper `reverseBelow` prop** — Responsive layout reversal using VueUse breakpoints; sections can stack in reverse order on mobile
- **PageSplit static gap map** — Fixes Tailwind CSS class purging for dynamic gap values

- **CaseStudy border tokens** — `border-neutral-800` → `border-default` for correct light/dark mode behavior

- **ProseA link component** — Simplified implementation
- **Umami provider** — Minor fix in events module

### Fixed

- **Dynamic Tailwind classes** — PageSplit now uses a static class map instead of template literal interpolation, preventing build-time purging
- **Console logging in production** — Replaced remaining `console.*` calls with evlog structured logging
- **Docs redirect middleware** — Path handling fix
- **Navigation composable** — Minor fix
- **Citation ID handling** — Fixed citation reference resolution
```

## Recommended Approach

### Option A: Release from main (Recommended)

1. Merge current branch to main first
2. On main: clean install, run full validation
3. Bump versions, update changelogs
4. Commit, tag, publish both packages
5. Create GitHub release

**Pros:** Clean environment, CI validates everything, proper git history
**Cons:** Requires merging first

### Option B: Release from this branch

1. Fix node_modules in this worktree
2. Run validation
3. Bump, changelog, commit, push
4. Merge to main, then publish from main

**Pros:** Can prep everything now
**Cons:** Worktree issues may persist; publishing should happen from main anyway

**Option A.** All prep work (changelog drafts, version bumps, doc updates) can be done now and committed. The actual `npm publish` should happen from main after merge to ensure CI passes.
